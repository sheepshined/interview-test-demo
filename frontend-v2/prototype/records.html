Q1 · 自我介绍
先用一分钟做个自我介绍吧。
我主要做 RAG 方向的落地，做过一个基于 LangGraph 的模拟面试系统：题库用 BM25 加向量双路召回、RRF 融合排序，会话侧用人在回路中断来等待用户作答，报告会按四个维度打分并给出学习建议。
评分 8.5 · 结构清晰
Q2 · 检索链路
请说说你的 RAG 项目里，从文档到召回的完整链路是怎样的？为什么要引入重排？
文档先按语义边界切块，长文走父文档策略：子块建索引、父块作为返回单元。召回时 BM25 负责关键词命中，向量负责语义相近，两路各取 Top20 后用 RRF 融合。重排是把候选交给交叉编码器精排，因为双塔向量召回的相似度是粗粒度的，重排后 Top3 的命中率明显更稳。
评分 8.8 · 细节可信
Q3 · 评估与幻觉 · 已追问
你们怎么判断 RAG 的回答有没有幻觉？如果要你设计一套评估方案，你会用哪些指标，怎么构造评测集？
主要看回答是不是有支撑。可以用 Faithfulness 之类的指标，评测集的话……可以人工标一批数据来做验证，也可以让模型自己当裁判。
评分 6.2 · 缺少方法
追问 · 检索指标
如果检索本身没召回正确段落，你的评估方案能区分出来吗？
可以分开看，检索侧看 Context Recall 和命中率，生成侧看回答与上下文的一致性，两类问题要分开定指标。
评分 7.6 · 及时修正
Q4 · Agent 工具调用
你的系统里 Agent 是怎么决定调用哪个工具的？
用 Function Calling 把工具定义成 schema 交给模型，由模型输出调用意图，工程侧再做参数校验与重试。
评分 7.9
